# 0002 — v0.1 runtime, recovery, and distribution

Status: adopted for experimental v0.1.0 on 2026-10-24.

The [interface contract](../interfaces.md) clarifies specification v0.3 for the
implemented `kb.v1` wire format. The first release is experimental: tests and
synthetic observations support concrete behavior, not universal safety claims.

## Runtime choices

The direct runtime dependencies are pinned in [go.mod](https://github.com/matheus3301/kb/blob/main/go.mod):

| Dependency | Version | Purpose |
| --- | --- | --- |
| `github.com/spf13/cobra` | 1.10.2 | CLI command/flag adapter. |
| `github.com/modelcontextprotocol/go-sdk` | 1.8.0 | Official MCP SDK, stdio protocol handling. |
| `github.com/BurntSushi/toml` | 1.6.0 | Local configuration parsing. |
| `go.yaml.in/yaml/v3` | 3.0.5 | YAML syntax nodes and metadata parsing. |
| `golang.org/x/text` | 0.43.0 | Unicode normalization, case/accent folding. |

Use Go 1.27.3, explicit constructors, and standard library facilities for
composition and diagnostics. Fx/Dig, Viper, Afero, and a database are not runtime
dependencies. The lexical search implementation is local to the core, with an
in-process derived index and on-disk freshness checks. There is no embedded LLM.
The Go binary runs without Node; Node/npx is only an optional skill-install channel.

YAML edits preserve untouched presentation spans and unknown metadata. Meaningful
changes refresh generated metadata and invalidate active verification. Non-string
mapping keys are a JSON interoperability policy finding, not an OKF restriction.
Configuration is captured when the store opens; a long-lived MCP process must
restart to apply configuration changes.

## Transactions and recovery

Use an advisory shared/exclusive per-base lock on supported Linux and macOS
systems. Normal writes require a conformant pre-state and post-state. Repair is
an explicit `apply --repair` plan, may replace a complete document, and still
requires a conformant final state within operational limits. It does not invent
a type or migrate a legacy collection.

Prepare `.kb/state/pending.json` durably before publication, recording request
identity, before/after bytes, and the receipt. Synchronize same-filesystem
replacements, then persist the commit marker. Recovery rolls back before the
marker and rolls forward afterward. Reads return `RECOVERY_REQUIRED` without
note mutation; explicit recovery or a subsequent mutation resolves pending state.
Interrupted recovery is idempotent. External readers may see intermediate states;
advisory locking does not provide absolute isolation from external editors.

Durable receipts under `.kb/state/receipts/` have no expiry in v0.1. Request
hashing excludes `dry_run`; an identical retry replays the prior receipt before
checking now-stale preconditions. Reusing its key with different content fails.
Dry-run persists no receipt or note change. `.kb/cache/` is disposable derived
state; journal and receipts are not. Exporting a knowledge bundle is not an
operational-state backup.

## Distribution and evidence

Binary installation, skill installation, MCP registration, and workdir activation
remain explicit, separate actions. No global agent configuration is installed.
The knowledge bundle needs no AGENTS.md. The installed skill was explicitly
loaded in the [controlled consumer observation](../evidence/consumer/consumer-evidence.json);
that does not prove automatic activation across agents.

Build CGO-free Linux/macOS binaries for amd64/arm64. The release packaging command
prepares archives with checksums, English documentation, skill, MIT license, and
dependency notices; it does not publish them. The maintainer publishes the tag
and release manually after CI under the current user authorization. Independent
required approvals remain zero while the sole maintainer also authors PRs;
independent review remains recommended. No auto-merge or auto-release is configured.

The [recorded full validation](../evidence/validation.json) reports 88.4% statement
coverage, 102 top-level test functions, 314 named pass events including subtests
and seeds, seven fuzz targets, and four cross-build targets. These are one run's
results. [Performance measurements](../performance.md) miss the initial warm
search and RSS targets; no reindex benchmark result is claimed. Future changes
must preserve the existing gates rather than weakening them to match results.
